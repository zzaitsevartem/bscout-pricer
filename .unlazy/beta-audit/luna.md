# Luna audit: startup, auth, dependencies, restore, catalog/parsers

Audit scope: current checkout source and isolated local checks. I did not inspect or print any `.env` values. One import probe was executed from `backend/`; because `Settings` configures `env_file=".env"` (`backend/src/config.py:74`), it may have loaded that file implicitly. The probe emitted no settings or secrets. Avoid repeating imports in that cwd unless env loading is explicitly disabled.

## Verdicts

| Claim | Verdict | Evidence / limits |
|---|---|---|

The probe could implicitly load `backend/.env`; no secret values were emitted. This establishes import success in the available local venv, not a clean-install/container deployment. |

| 422 reflects submitted password | **Potentially confirmed for validation errors; no live HTTP request.** Registration password validation can raise a Pydantic field error (`backend/src/modules/auth/schema/auth.py:20,25-30`); FastAPI's normal request-validation response includes error `input` fields, so this response path can echo submitted password when the byte-length validator rejects it. The logging scrubber masks password-shaped keys (`backend/src/logging_config.py:20-37`), which does not sanitize HTTP response JSON. Validate against the deployed FastAPI/Pydantic versions before treating this as observed runtime output. |
