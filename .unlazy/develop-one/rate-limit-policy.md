# Политика этапа 1

Инвентаризация объявлений маршрутов: routes.txt; все запросы проходят middleware.
- Общий бюджет 120/60 секунд (settings); анонимный IP, для проверенного access JWT — user ID.
- Поиск/товары/устройства: дополнительно 90/60 секунд.
- Auth credentials/password/email/OAuth: 10/300 секунд по IP, включая авторизованных.
- Проверка доступности username и refresh/logout используют общий бюджет: штатное обновление сессии не расходует бюджет попыток входа.
- Export, parser и изменения admin/import/broadcast: дополнительно 10/60 секунд.
- Остальные изменения: 30/60 секунд.
- Webhook: отдельные 600/60 секунд, без общего пользовательского бюджета; 429/503 с Retry-After позволяют провайдеру повторить доставку. Верификация и атомарность платежей остаются у разработчика 2.
- Health и OPTIONS освобождены; readiness самостоятельно проверяет зависимости.

Redis Lua атомарно удаляет истёкшие элементы, проверяет размер и добавляет запрос; отказ не продлевает окно. Общий namespace между процессами, TTL окон+1; IP/user identity хешируются в ключах. При отказе Redis чтение/refresh/logout продолжаются; credential, write, expensive и webhook возвращают 503 с Retry-After=5. Timeout проверки ограничен одной секундой; сырые исключения подключения в лог не выводятся.

Причина политики: сохранить просмотр и возможность выхода при сбое защиты; запретить обход ограничений подбора пароля, отправки писем и дорогих изменений. Webhook получает временный отказ, чтобы внешний провайдер повторил событие, вместо незащищённого вызова его API.

Forwarded headers проверяются middleware по peer CIDR справа налево. Uvicorn не переписывает peer до этой проверки; TrustedProxyMiddleware отдельно принимает http/https X-Forwarded-Proto только от доверенного peer, чтобы HTTPS slash-redirect не понижался до HTTP; nginx перезаписывает входной XFF реальным remote_addr. Production edge использует настраиваемый EDGE_SUBNET, тот же CIDR передаётся middleware. При существующей сети смена subnet потребует пересоздания этой Docker-сети; deploy здесь не выполнялся. Вне compose надо явно задать RATE_LIMIT_TRUSTED_PROXIES либо оставить доверие отключённым.

Фоновые задачи Celery не являются HTTP-клиентами и не используют пользовательский бюджет. Их существующие блокировки и ограничение full-sync не менялись.
