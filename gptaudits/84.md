Продолжение 82/83. Исправление относится к общему сценарию, без model-specific production условий и без тестов на конкретную Sony.

## Что изменено в этом продолжении

- Добавлена общая регрессия extractor с двумя синтетическими alias: обрезанный/добавленный суффикс модели не считается fuzzy совпадением, настоящее совпадение и замена одной буквы сохраняются.
- В GET списка кандидатов для pending выполняется текущий extractor и сравниваются device/part с кластером предлагаемого продукта. При расхождении или отсутствии распознанной модели/детали API возвращает `validation_warning`; UI показывает предупреждение рядом с товаром. Словари и кластеры загружаются пакетно на страницу, без запросов на каждую строку.
- Предупреждение НЕ меняет сохранённый статус, score, features и decided_by/at, не скрывает кандидатов и не блокирует ручной approve. Никакой 409 guard не возвращён. Для моделей без кластеров предупреждение пока не вычисляется.
- Усилены нейтральные approve/search тесты: проверяются отсутствие предупреждения у корректной связи и source offer ID/URL после approve. Тест ручного override проверяет предупреждение и сохранённое pending решение перед успешным approve.

Один из них теперь распознаёт другую модель, остальные могут быть нераспознаны. Это не основание записать 113 admin rejects. Все оставлены pending, история не менялась.
